    RISCV代理内核实验：系统调用、异常和外部中断（三）系统调用、异常和外部中断的实现

    系统调用（@lab1_1）

    你是一名程序员，你想要在屏幕上打印 “Hello, World!”。

    但是你发现，普通的用户程序没有权限直接操作显示器硬件，你需要通过“系统调用”请求操作系统帮你完成这个任务。就像你去餐厅吃饭，难道要自己进厨房做饭吗？只需要告诉服务员（操作系统）你的需求，由他们去厨房（内核）完成。经验上说，厨子做饭更专业，效率也更高。

    在RISC-V架构中，系统调用通常通过 ecall 指令来触发。当用户程序执行 ecall 指令时，处理器会切换到内核模式，并跳转到预定义的异常处理程序。在这个处理程序中，操作系统会根据用户程序传递的参数来确定需要执行的具体服务（例如打印字符串）。

    当用户程序执行 ecall后，RISC-V CPU的硬件会自动且原子性地完成以下关键操作：

    1. sepc ← PC，sepc保存了用户程序执行 ecall指令的下一条指令地址，以便在系统调用处理完成后能够返回继续执行用户程序。
    2. scause ← 8，表示环境调用 from U-mode
    3. sstatus.SPIE ← SIE，保存之前的中断使能状态
    4. SIE ← 0，防止在处理陷阱时被其他中断打断
    5. sstatus.SPP ← U-mode（0），切换到S-mode
    6. PC ← stvec，跳转到内核的异常处理程序

    中断/异常处理完成后，内核通过执行 sret指令返回用户程序，sret会自动完成以下操作：

    1. PC ← sepc，返回到用户程序的下一条指令
    2. SIE ← sstatus.SPIE，恢复之前的中断使能状态
    3. CPU 的特权级恢复为 sstatus.SPP（U-mode）

    异常（@lab1_2）

    机器模式最重要的特性是拦截和处理异常（不寻常的运行时事件）的能力。 RISC-V将
    异常分为两类。一类是同步异常，这类异常在指令执行期间产生，如访问了无效的存储器
    地址或执行了具有无效操作码的指令时。另一类是中断，它是与指令流异步的外部事件，
    比如鼠标的单击。 ——《RISC-V手册》

    跟我们在ICS课上学的不同，异常不分为trap、fault和abort三类（这种分类方式源自 x86架构）。RISC-V中，trap（陷入）是最顶层的概念，它是一个总称，涵盖了所有导致处理器正常指令执行流被中断，并跳转到更高特权模式下特定处理程序执行的事件。

    在trap的范畴下，主要分为两大类：异常（Exception）和 中断（Interrupt）。这两者的区别在于：

    • 异常（Exception）：是由当前执行的指令引起的事件，通常是由于程序错误或非法操作导致的。例如，除零错误、非法指令等。
    • 中断（Interrupt）：是与当前执行的指令无关的事件，通常是由外部设备或定时器触发的。例如，定时器中断、I/O设备中断等。

    外部中断（@lab1_3）

    外部中断是由外部设备（如定时器、I/O设备等）触发的中断信号。当外部中断发生时，处理器会自动切换到内核模式，并跳转到预定义的中断处理程序。

    在本实验中，我们通过定时器中断来演示外部中断的处理。当定时器中断发生时，处理器会跳转到内核的定时器中断处理程序。在该处理程序中，操作系统可以执行一些定时任务，例如更新系统时间、调度任务等。

    在RISC-V架构中，定时器中断通常通过 mtime和 mtimecmp寄存器来实现。当时钟脉冲到达时，mtime寄存器的值会增加。当 mtime的值达到 mtimecmp寄存器中设置的值时，RISC-V的CLINT（核心本地中断器）会触发一个机器模式定时器中断 MTIP。在多核处理器中，每个硬件线程 hart都拥有自己独立的 mtimecmp寄存器。

    一旦定时器中断被触发，必须向 mtimecmp寄存器写入一个未来的时间值（大于当前的 mtime），以清除中断挂起标志。通常通过将目标 TIMER_INTERVAL加到当前的 mtime值上来实现。

    操作系统通过灵活设置 mtimecmp 的值，为系统调度提供时间基准。进程时间片轮转调度、维护系统时钟（jiffies）以及实现高精度睡眠函数（如nanosleep）等都是其典型应用场景。

    本实验中，中断代理包括 MIP_SSIP（软件中断）、MIP_STIP（定时器中断）和 MIP_SEIP（外部中断），但并不包含 MIP_MTIP（机器态定时器中断），因此，当定时器中断发生时，会由M态内核处理该中断。

    为什么1,000,000个时钟周期内，wait了约10,000,000次循环迭代？

    MTIME 不是 CPU 时钟！ RISC-V 规范并没有规定 MTIME 必须与 CPU 时钟同步。实际上，MTIME 通常是由一个独立的时钟源驱动的，这个时钟源的频率可能与 CPU 时钟不同。比如，CPU 可能以 1 GHz 的频率运行，而 MTIME 可能以 10 MHz 的频率运行。
