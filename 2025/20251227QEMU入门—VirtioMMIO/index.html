    QEMU入门（3）Virtio MMIO

    struct VirtioMMIO字段解析

    关键寄存器列表

    Offset 名称 类型 读写流程中的作用
    0x000 MagicValue R 驱动读取，确认确实是 VirtIO 设备
    0x010 DeviceFeatures R 驱动读取，了解设备支持的功能（如多队列）
    0x030 QueueSel W 驱动写入，指定后续操作针对哪一个队列
    0x050 QueueNotify W 最频繁写入，通知设备“有活干了” (Kick)
    0x060 InterruptStatus R 驱动在中断里读取，看是哪类事件（配置改变或数据处理完）
    0x064 InterruptACK W 驱动写入，告诉设备“我知道了”，清除中断位
    0x070 Status RW 驱动维护，报告驱动的初始化阶段（ACK/DRIVER/OK）

    Virtqueue

    Virtqueue 是 VirtIO 协议的核心，是 Guest 和 Host 之间共享的一块环形缓冲区（Circular Buffer）。一个队列由以下三部分组成：

    Descriptor Table（描述符表）

    这是存放“数据指针”的地方。每个描述符（Descriptor）固定占用 16 字节。

    • Address (8 bytes): 指向数据在 Guest 内存中的真实物理地址。
    • Length (4 bytes): 该段数据的长度。
    • Flags (2 bytes):
      • NEXT: 表示当前数据还没完，后面还连着一个描述符（链式结构）。
      • WRITE: 表示这块内存是让 Device 写入的（如读磁盘），否则是 Device 读取的（如写磁盘）。
    • Next (2 bytes): 如果设置了 NEXT 标志，这里存放下一个描述符在表中的索引 。

    Available Ring（可用环）

    这是 Guest（驱动） 用来告诉 Host（设备） 哪些描述符已经准备好被处理了。

    • Flags: 用于控制是否需要中断提醒。
    • Idx (Index): 记录 Guest 下一次写入的位置。这个索引是一直累加的，通过取模来定位。
    • Ring Array: 存储的是描述符表的索引值。

      流程： Guest 把数据放进描述符表第 5 号位置，然后把 “5” 这个数字写进 Available Ring 的当前空位，再更新 Idx。

    Used Ring（已用环）

    这是 Host（设备） 用来告诉 Guest（驱动） 哪些描述符已经处理完毕。

    • Flags: 用于控制是否需要 Guest 发送通知。
    • Idx: 记录 Host 下一次写入的位置。
    • Used Elements Array: 这里的每个条目包含：
      • id: 处理完的描述符链的头部索引。
      • len: 实际写入数据的长度（对于写操作非常重要）。

    三者的协作流程 (Data Flow)

    我们可以用“生产者-消费者”模型来理解这个过程：

    1. Guest 生产请求：
    • 在 Descriptor Table 中填充数据地址。
    • 把该描述符的索引放到 Available Ring 中。
    • 更新 Available Ring 的 Idx。
    • 写 MMIO 寄存器（Kick），通知 Host。
    1. Host 消费请求：
    • 从 Available Ring 拿到描述符索引。
    • 根据索引去 Descriptor Table 找内存地址，读取或写入数据。
    • 处理完后，把描述符索引和处理长度放入 Used Ring。
    • 更新 Used Ring 的 Idx。
    • 触发中断，通知 Guest。
    1. Guest 收尾：
    • 从 Used Ring 发现任务完成，回收描述符，处理返回的数据。

    工作流程解析

    写入信号流：Guest -> Host (Kick)

    当 Guest OS 需要发送数据时，典型的寄存器读写流如下：

    1. 准备数据： Guest 在内存中填好 Virtqueue 的 Descriptor Table。
    2. 选择队列： Guest 向 QueueSel 写入索引（例如 0），告诉硬件接下来要操作哪个队列。
    3. 确认就绪： Guest 检查 **QueueReady**，确保队列已激活。
    4. 触发通知 (Kick)： Guest 向 QueueNotify 写入该队列的索引。
    • 底层动作： 这一步会产生一个 VM-Exit。
    • Host 视角： KVM 捕获到该地址的写入异常，将控制权交给 QEMU（或 vhost），后端开始处理内存中的数据。

    读取信号流：Host -> Guest (Interrupt)

    当后端处理完请求（如磁盘读取完成），它需要通知 Guest：

    1. 更新内存： Host 将结果写入 Virtqueue 的 Used Ring。
    2. 设置状态： Host 修改 InterruptStatus 寄存器的位，标记有新的配置更改或已处理的队列。
    3. 注入中断： Host 通过 KVM 向 Guest 注入一个虚拟中断（IRQ）。
    4. Guest 响应：
    • Guest 的中断处理程序读取 InterruptStatus 确认中断原因。
    • Guest 向 InterruptACK 写入位，以清除中断信号。
    • Guest 从内存中读取处理后的数据。
