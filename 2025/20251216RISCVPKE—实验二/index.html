    本实验需要实现 void user_vm_unmap(pagetable_t page_dir, uint64 va, uint64 size, int free)函数，用于解除用户虚拟地址与物理地址的映射关系，并释放对应的物理页。

    我们要做的事情有：

    • 将虚拟地址 va对应的物理页页表项清除。
    • 如果 free参数为真，则释放该物理页： 将该页插入空闲页链表中，以便后续分配使用。

    lab2_3 简单缺页异常处理

    缺页异常有哪些情形？

    • 访问了不在页表中的虚拟地址。

      • 例如，分配的栈页用完了，访问了栈底下的地址。
      • 例如，访问了尚未分配的堆地址。
      • 例如，访问了未映射的代码段地址（COW机制，初始只加载部分代码段）。

    • 访问了权限不够的虚拟地址。

      • 例如，访问了只读页却试图写入数据。
      • 例如，用户态程序试图访问内核态地址。

    本实验我们需要实现 void handle_page_fault(uint64 va)函数，处理 CAUSE_STORE_PAGE_FAULT和 CAUSE_LOAD_PAGE_FAULT两种缺页异常，由硬件在执行 load 或 store 指令时触发，并将目标地址地址存储在 stval寄存器中。

    当用户程序访问了未登记的地址时，我们需要为其分配一个新的栈页，并将其映射到对应的虚拟地址上。

    分配是简单，但我们也要做一些检查工作：

    • 范围检查：确保访问的地址在用户栈的合法范围内。
    • 权限检查：确保访问的地址具有读写权限。

    在 memlayout.h中，USER_FREE_ADDRESS_START定义了用户空间可用的最低地址，其值为 0x00000000 + PGSIZE * 1024 = 0x00400000，表示用户空间的前4MB地址不可用，一般用于加载用户进程的代码和数据。

    可以看到，编译器默认将用户程序的代码段从 0x10000地址开始加载，而这之前的地址不可用，一般用于安全考虑，比如捕捉空指针引用。

    而从 0x00400000开始到 USER_STACK_TOP（0x7ffff000）是用户空间可用的地址范围，一般用于分配堆和栈。

    memlayout.h中，存在宏 STACK_SIZE 4096，但实际上已给出的代码中并未使用。我们假设这是栈的最大大小限制，那么单位是什么呢？如果是字节，那4KB似乎太小了，如果是页，即用户栈最多能分配4096页（16MB），这样更合理一些。参考现代Linux系统的默认栈大小一般为8MB，而Windows系统的默认栈大小一般为1MB。

    用户栈的起始地址为 USER_STACK_TOP - STACK_SIZE * PGSIZE = 0x7ffff000 - 4096 * 4096 = 0x7efff000。所以堆的地址范围为 0x00400000到 0x7efff000，有大约2GB的虚拟空间可用。

    有了范围，我们就可以在缺页异常处理函数中检查访问的地址 va是否在用户栈的合法范围内

    • 如果不在范围内，说明访问了非法地址，直接终止进程。
    • 如果在范围内，则分配一个新的物理页，并将其映射到对应的虚拟地址上，权限为读+写。

    lab2_challenge1 复杂缺页异常处理

    lab2_3中，我们只粗略的检查了导致缺页错误的访问地址是否位于可用逻辑空间内[USER_FREE_ADDRESS_START, USER_STACK_TOP]，但这段范围内：

    1. [USER_FREE_ADDRESS_START, g_ufree_page]：这是已分配的用户堆的地址范围
    2. [g_ufree_page, USER_STACK_TOP - STACK_SIZE * PGSIZE]：这是未分配的堆地址范围
    3. [USER_STACK_TOP - STACK_SIZE * PGSIZE, sp]：这是未分配的栈地址范围
    4. [sp, USER_STACK_TOP]：这是已分配的用户栈的地址范围

    读写2和3范围内的地址，都是非法访问，会导致缺页异常。但二者的处理方式不同：

    • 访问2范围内的地址，属于堆空间，是由用户自行分配管理的。如果访问了未分配的堆地址，说明用户程序有bug，应该直接终止进程。
    • 访问3范围内的地址，属于栈空间，是由操作系统自动分配管理的。如果访问了未分配的栈地址，说明用户程序需要更多的栈空间，操作系统应该为其分配一个新的栈页，并将其映射到对应的虚拟地址上。
